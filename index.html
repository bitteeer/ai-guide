それ以外は確認なしで使えます 必読

社内で契約しているGemini・Claude・ChatGPT・Canvaは学習に使われない設定です。案件資料、原稿、議事録、社内の数値など、都度確認せずに使ってください。

個人のパスワードや社外秘の情報は、共有範囲に注意してください。プロジェクトの参照資料に置くと、そのプロジェクトを使える人全員が見られます。

ただし、次の場合は例外です。

  • 先方との取り決めがある案件。AIを使えない場合と、使うツールが指定されている場合があります。ツールを指定されたときは、個人アカウントで使わないでください
  • 学習に使われるツール（Google AI Studioの無料枠、Google Flow、Microsoft Copilotの個人版）。社外に出せない情報は入れないでください

アカウントと履歴 必読

  • 業務では会社のアカウントを使ってください。学習オフは会社アカウントのみの設定で、個人アカウントには適用されません
  • ChatGPTは共有アカウントのため、会話履歴が全員に見えます。見られたくないやりとりは一時チャットを使うか、終わったら削除してください

成果物を他人に共有するときに確認すること 必読

AIが書いたものでも、責任を負うのは出した本人です。とくに数字・人名・法令は必ず確認してください。

人が確認・修正した原稿は、通常の成果物と同じ扱いです。納品も告知も、AIを使わない場合と変わりません。ただし先方が制作過程の開示を求める場合や、契約でAI利用の申告が定められている場合は、それに従ってください。

薬機法・景表法のチェック

一次チェックに使って構いません。見落としを減らす目的では有効です。

ただしハルシネーションは仕組み上避けられず、法令の解釈はとくに間違えます。AIが指摘した箇所を人が確認する、という向きで使ってください。

AIが指摘しなかった＝安全、ではありません。

著作権と社外公開

AIが生成したものは、既存著作物に酷似することがまれにあります。次のいずれかに当てはまるものは、公開前に上長に確認してください。

  • 実在の人物や著名人に似た人物が写っているもの
  • 既存のキャラクター・作品に似せたもの
  • 他社のロゴ・商標に似た要素が入っているもの

3つとも当てはまらなければ、確認は不要です。

入れてはいけない情報を入れてしまったら 必読

まず、その会話を削除してください。履歴からすぐ消え、サーバー上からも各サービスの規定に沿って削除されます（ClaudeとChatGPTは30日以内）。Gemini・Claude・ChatGPTは外部学習に使われない設定なので、モデルに残ることはありません。

次の場合だけ、当日中に上長に報告してください。

  • 削除では消えない場所に入れた（プロジェクトやGPTsの参照資料、共有リンク、MCPで別サービスに書き出したあと）
  • 他の人が見た可能性がある（共有アカウントなど）

自分の会話に少量入れて、すぐ削除した場合は報告不要です。

分類の一覧 必読

分類の基準は成果物がどこに残るかとどこまで自走するか。中身のAIはどれもほぼ同じで、性能差より設計思想の差が効きます。

分類代表成果物の置き場所動き方
チャット型Claude / ChatGPT / Gemini会話の中一往復で答える（Deep Research使用時は数分〜十数分自走）
作業代行型Cowork / ChatGPT WorkPCのフォルダ（Cowork）、生成ファイル（Work）複数手順を自走。定期実行も可
開発型Claude Code / Codexコードとして手元に残る同上＋履歴管理・動作確認
制作型Claude Design / Gemini / ChatGPT / Higgsfield / AI Studio / Google Flow / Vids / Canva画像・動画・音声のファイル指示から素材を生成し、書き出して使う

分類は「主にどう使うか」の目安で、厳密な線引きではありません。複数の型にまたがるツールがあります。
・Google AI Studio … 素材の生成（制作型）に加え、APIキーの発行や、サーバー処理・DB・認証つきのWebアプリ作成（開発型に近い）もできます
・Gemini / ChatGPT … 相談（チャット型）と画像生成（制作型）の両方

自動化に向かない業務

  • 例外処理が多い業務（毎回イレギュラーが発生する）
  • 正解が一つに定まらない創造的判断
  • 相手の感情が絡むコミュニケーション
  • 一度の判断ミスが致命的になる（クレーム・契約・法的責任に直結する）
  • 長年の経験で判断していて数値化・言語化できないもの

無理に自動化すると、手戻りのコストが削減分を上回ります。

第 4 部

導入の進め方

3段階で進める 必読

やること
① 手作業でやる自分で1回やる。手順・合格条件・見本を残す
② 半自動で回すAIに作らせ、毎回人が確認する。精度と例外が見える
③ 全自動にする定期実行に載せるのは最後

①で残した3つは、そのまま②で使えます。手順は指示文になり、見本はAIに例として渡せます（第8部「使い方のコツ」）。

合格条件を先に決めてください。AIの出力は質が低くても文章が整っているため、基準がないと「なんとなく良さそう」で通してしまいます。人の下書きと違い、粗さが見えません。

完成形まで決める必要はありません。アイデア出しのように正解が定まらない業務では、完成形を先に決めるとAIは想定内のものしか返しません。「既存案と被らない」のような合格条件だけで足ります。

②を飛ばすと、チェックしているつもりで何も判定していない状態になります。最初の1〜2か月は人が見る前提で。

コードとプロンプトの違い

答えが決まっている作業はコード（開発型）、判断が要る作業はプロンプト（チャット型）です。

コードプロンプト
実行するものコンピュータAI
同じ入力を与えたら必ず同じ結果毎回少し変わる
向いている作業決まった手順の反復判断・言語化・発想

「1,000件のCSVを合計する」はコード、「この広告の共通点を言語化する」はプロンプトです。

この切り分けが、そのまま自動化できる範囲になります。コードの部分は全自動にでき、プロンプトの部分は結果が揺れるため半自動に留まります。

実例：大量クリエイティブの分析

「1,000件のクリエイティブと数値を取り込み、勝ちパターンを資料化して次の案を出す」場合の組み方です。

工程やること使うもの度合い
① 取り込みURLから画像と数値を収集開発型（Squad beyond・動画広告分析PROのMCP）全自動
② 絞り込み数値だけで上位・下位を抽出開発型全自動
③ 言語化上位20件・下位20件の画像だけを見せて共通点を出す開発型 チャット型半自動
④ 資料化勝ちパターンをレポートにまとめる開発型 作業代行型半自動
⑤ 案出し案件・ターゲット・訴求を指定して台本案を複数出すチャット型半自動
⑥ ビジュアル化案を実際の画像にする制作型（Higgsfield）半自動

Chatwork / Slackへの通知まで含めれば、毎月の作業が一度の指示で回ります。②で数値だけを使って絞るのが要点です。1,000枚すべてを見せると時間もコストもかかりますが、③に渡るのは40枚で済みます。

⑤で「どのターゲットに、どの訴求で攻めるか」を決めるのは人です。分析結果は過去に勝ったものなので、方針まで任せると過去のなぞりになります。①〜④は毎月同じ手順なので、開発型が適します。

専門家をつくる（カスタムAI）

同じ依頼を3回繰り返したら、専用のAIを作ってください。役割と参照資料を持たせて残しておけます。「自社のトーンで書く広報担当」のようなイメージです。

ツール呼び方持たせられるもの
GeminiGem役割の指示、参照ファイル
ChatGPTGPTs（マイGPT）役割の指示、参照ファイル、外部連携
Claudeプロジェクト役割の指示、参照資料をまとめて保持
Cowork / Claude Codeスキル手順そのものを型として登録

持たせるのは、役割・参照資料・出力形式の3つです。書き方は第5部「頼み方の基本」と同じです。参照資料には社内規程、過去の良い成果物、用語や表記のルールを入れます。

エージェントとの違い。専門家は前提を持った相談相手、エージェント（作業代行型・開発型）は手順を実行する担当者です。

中に入れた資料は、その専門家を使う人全員が見られます。共有範囲を確認してから入れてください。

WEBサイト化して共有する

GitHub PagesかNetlifyに置けば、URLで共有できます。どちらも無料枠があり、HTMLファイルを上げるだけです。Claudeのアーティファクト、Coworkが出したファイル、Claude CodeやCodexで作ったツールも、すべてHTMLファイルとして書き出せます。

必ず検索避けを設定してください。HTMLの<head>内に次の1行を入れると、GoogleやBingの検索結果に出なくなります。

<meta name="robots" content="noindex, nofollow">

ただし検索避けをしても、URLを知っている人は誰でも見られます。社外に出せない内容は載せないでください。

第 5 部

出力の質を上げる

頼み方の基本 必読

やることそのまま使える指示
役割を与える「経験10年の広報担当として書いてください」
読み手と用途を伝える「クライアントの役員会で配る資料です」
形式を先に決める「見出し3つ、各200字、箇条書きは使わない」
やってほしくないことを書く「専門用語は使わない。断定は避ける」
例を見せる「過去に評価が高かった原稿を貼ります。この文体に寄せて」
足りない情報を聞かせる「情報が足りなければ、書き始める前に質問して」
選択肢を出させる「案を3つ、それぞれ長所と短所も」
過程を書かせる「結論の前に、判断の根拠を先に書いて」

長い資料は先に貼り、指示は最後に書いてください。指示が資料の前にあると薄れます。

思い通りにならないときは、言い方を変えるより材料を足してください。プロンプトの文言を調整するより、渡す資料を整えるほうが効果が大きい傾向があります（コンテキストエンジニアリング）。

プロンプトをAIに作らせる

書き方が分からないときは、指示文そのものを頼めます。

「〜をやりたい。そのためのプロンプトを書いて。情報が足りなければ質問して」

手持ちの指示文を貼って「足りない要素を指摘して」と頼む使い方もできます。

できたプロンプトは新しい会話に貼って使ってください。同じ会話だと、作る過程のやりとりに引きずられて、素の状態で効くか確認できません。

うまくいったものは第4部の「専門家をつくる」に登録すると、次から書かずに済みます。

設定を上げる

頼み方を工夫するより、設定を上げるほうが速い場面があります。

  • モデル … 迷ったらSonnet 5。物足りなければOpus 5やFable 5に上げる
  • エフォート … 基本は「高」。込み入った検討や見落としが怖い作業は「超高」「最大」に上げる

時間とコストは増えます。単純作業まで上げる必要はありません。

話題が変わったら新しい会話を立ててください。会話は毎回すべて読み直されるため、長くなるほど遅くなり、前の話題に引きずられます。

事実の誤りを減らす 必読

ハルシネーションはゼロにできません。次の4つで減らします。

やることそのまま使える指示
資料を渡す一般知識で答えさせず、手元の資料から答えさせる。資料限定型（Gemini Notebook）が確実です
出典を求める「どこに書いてあるか、該当箇所を引用して」
わからないと言わせる「不明な点は推測せず、不明と書いて」
同じ質問を2回する答えが変わる箇所は疑ってください

レビューさせる

出したものは、AI自身にチェックさせられます。

「この文章の弱いところを3つ挙げて。事実の誤り、論理の飛躍、読み手に伝わらない箇所の観点で」

同じ会話の中で聞くと、自分の出力をかばいます。別の会話に貼るか、別のツールに渡してください。ClaudeとChatGPTでは違う指摘が出ます。

敵対的検証

AIは同意しがちです。「これでいいと思う？」と聞けば、たいてい良いと答えます。反対側を明示的に書かせてください。

「この案が失敗するとしたら、原因は何か。5つ挙げて」
「クライアントから来る指摘を想定して、5つ挙げて」
「この主張に反対する立場から反論を書いて」

使いどころは2つあります。企画が固まったあと（弱点を先に潰す）と、成果物を出す前（指摘される前に直す）。どちらも人に見せる前に一度通してください。

ツール別の詳細

Claudeクロード チャット型 必読

Anthropic社のAIアシスタント。長文の読み書き、機微な文書、推敲に強みがあります。

  • 向いている：相談、下書き、推敲、資料を貼っての質問
  • 向かない：手元のファイルを直接書き換えること、繰り返し実行する作業

アーティファクト

資料・グラフ・簡易ツールを、会話とは別枠で作ってその場で開けます。この資料もアーティファクトとして作りました。呼び方はツールごとに違いますが、同様の機能は他のチャット型にもあります。

配り方は第4部の「WEBサイト化して共有する」にあります。

Claude Code 開発型 必読

コードを読み書きするAIエージェント。やりとりはチャット形式で、日本語で指示できます。ターミナルが原点ですが、デスクトップアプリ・Web・VS Codeなどのエディタ拡張でも同じことができます。

  • 向いている：継続的に手を入れるコード、手順が固定した業務自動化
  • 向かない：一度きりの書類作成

Coworkコワーク 作業代行型 必読

フォルダを渡すと、中のファイルを読んで成果物を作り、そのフォルダに書き戻します。ファイルを1つずつアップロード・ダウンロードする必要がありません。

  • 向いている：フォルダ内の資料整理、1枚で完結するツール
  • 向かない：継続的に育てるコード。作業環境が毎回リセットされ、変更履歴も残らない

Claude Design 制作型

テキスト指示でUI・バナー・LP・資料のビジュアルを生成します（2026年4月公開）。社内のロゴ・配色・コンポーネントをデザインシステムとして読み込ませると、それに沿った成果物を出せます。Claude Codeとの双方向連携、Canva・Adobe・Miroへの書き出しに対応。

  • 向いている：ブランドを揃えたバナー・資料・画面デザインの量産
  • 向かない：文章中心の作業

ChatGPT チャット型 必読

OpenAI社のAIアシスタント。利用者が最も多く、参考情報も豊富です。

  • 向いている：汎用的な相談、下書き、アイデア出し、画像生成
  • 画像生成（Images 2.0）：2026年4月から、ChatGPT・Codex・APIのいずれからも利用可。日本語テキストの描画精度が高く、1回で最大8枚まで同時生成。商用利用可。思考モードはPlus以上

ChatGPT Work（作業代行型）

2026年7月から、ChatGPTの中で複数手順を自走して成果物を作る機能が使えます。同時にデスクトップアプリが作り直され、チャット・Work・Codexが1つのアプリに統合されました。Coworkとの違いは成果物の置き場所で、WorkはExcelやWordを生成して返すのに対し、Coworkは手元のフォルダを直接書き換えます。

エージェントモード

ブラウザを操作して調べ物から資料作成までこなします。ファイル削除や送信など取り消せない操作の前には必ず確認が入ります。月あたりの実行回数に上限があります。

Codexコーデックス 開発型 必読

OpenAI社の開発者向けエージェント。Claude Codeと同じ位置づけです。

  • 向いている：コードを書く・直す、手順が固定した業務自動化
  • 画像生成：Images 2.0 を Codex から呼べるため、生成して組み込む流れが1環境で完結する

Claude Codeとの選び方。普段使っているサービス側に合わせるのが基本です。ただし得意分野が違うので、重要な作業では両方に投げて出力を比べる使い方もできます。

Geminiジェミニ チャット型

Google社のAI。社内ではGoogle Workspaceに含まれているため、全員が追加契約なしで使えます。ドキュメント・スプレッドシート・Gmailの中からも呼び出せます。

  • 向いている：Google Workspace上の作業全般、画像生成、図解の作成
  • 向かない：PC内のファイルを直接書き換えること、繰り返し実行する作業（Googleドキュメントやスプレッドシートの編集はできます）

画像生成（Nano Banana系）

接続時の注意

  • 権限を絞ってから接続する。接続したアカウントが見られる範囲は、AIも見られます。管理者権限のアカウントで気軽につながないでください
  • 書き込み権限は慎重に。freeeのように基幹業務を操作できるものは、まず読み取りだけで運用を始める
  • 外部から来た文書に注意。プロンプトインジェクションの入口になります（第8部の用語集を参照）
  • レート制限を確認する。サービスごとに1分あたりの上限があります。大量処理では詰まるため、事前に確認してください

新しく接続したいとき

  2. 権限を確認する。読み取りだけで足りるか、書き込みまで必要かを決める
  3. 承認後に接続する。
  4. 使わなくなったら解除を申告する。つなぎっぱなしが一番危険です

APIを使うかどうか

社内契約ツールはサブスクリプション、APIは従量課金です。数千件規模をまとめて処理するなら、事前に試算して上長に相談してください。少量であればアプリを使用してください。

第 8 部

用語集

基本 必読

生成AI
文章・画像・コードなどを新しく作り出すAI。検索が既存の情報を探して見せるのに対し、生成AIはその場で組み立てます。そのため、世の中にまだ存在しないものでも作れます。手元の資料や数値を読ませれば、それに沿った叩き台がその場で出てきます。
LLM（大規模言語モデル）
ChatGPTやClaudeの中身。「次に来る言葉」を予測する仕組みで動きます。意味を理解しているというより、それらしい続きを高い精度で組み立てているのが実態です。
プロンプト
AIへの指示文。出力の質はここでほぼ決まります。
マルチモーダル
文字だけでなく画像・音声・PDFも扱えること。
API
プログラムからAIを呼び出す仕組み。アプリの画面を経由せず自社システムに組み込むときに使います。料金はトークン単位の従量課金。

精度と限界

ハルシネーション
事実でないことを自信のある書き方で出力する現象。仕組み上どうしても発生し、故障ではありません。減らし方は第5部にあります。
知識のカットオフ
モデルは学習した時点のデータで作られ、その後の出来事は入っていません。新しい製品や価格、法改正などを古い情報のまま答えます。「知らない」とは言わないのが厄介な点です。最近の情報が必要なときは、検索機能を使うか資料を添付してください。
画像認識
AIは画像を目で見ているわけではありません。画像を格子状のブロックに分割し、数値に変換して文章と同じ流れで処理しています。人間の視覚とは別物なので、次の制約が出ます。
  • 細部は潰れる。画像は縮小されてから処理されるため、小さな文字や細かい数値は読めません。確認したい箇所は拡大して切り出して渡してください
  • 位置と個数が苦手。「左から3番目」「何個あるか」はずれることがあります
  • 画像内の文字は誤読する。重要な数値は画像ではなくテキストで渡す
  • 見えない部分を補完する。不鮮明な箇所をもっともらしく埋めます。画像でもハルシネーションは起きます

クリエイティブ分析では、色調・構図・人物の有無といった大きな特徴は拾えますが、文字サイズや細かい配置は当てになりません。細かい要素はタグとして数値データ側に持たせるほうが確実です。

根拠を持たせる

Deep Research
AIが何十件もWebを検索し、出典付きのレポートにまとめる機能。Claude・ChatGPT・Geminiにあります。数分〜十数分。引用元が個人ブログのこともあるため、リンクを開いて確認する手間は残ります。
グラウンディング
出力を実在の情報源に紐づけること。検索結果や添付資料を根拠にさせると、ハルシネーションが減り、出典を確認できます。
RAG（検索拡張生成）
指定した資料に基づいて答えさせる仕組み。資料限定型はこれに特化したツールです。

分量とコスト

トークン
AIが文章を処理する単位。日本語は1文字＝1〜2トークン。料金や上限はこの単位で数えます。
依頼の例トークン目安
「これ英語で何て言う？」〜100
メールの下書き約1,000
議事録の作成（A4 2〜3枚）約8,000
画像1枚を見せて質問約1,000〜2,000
60分の文字起こしを要約約30,000
30ページのPDFを要約約60,000
100ページの規程集をチェック約150,000〜
コンテキストウィンドウ
一度に扱える上限。2026年時点のClaude（Sonnet 5 / Opus 5）は100万トークン、Geminiも同程度です。「先に伝えたのに反映されない」の正体はこれですが、上限自体は年々広がっています。

モデルと設定 必読

モデル
AIの種類・世代。同じサービスでも選ぶモデルで賢さ・速さ・コストが変わります。難しい仕事は高性能モデル、単純作業は軽量モデルが基本です。
Claudeのモデル（※2026年8月時点）使いどころ
Fable 5最上位。最難関の検討や、長時間動かすエージェント向け
Opus 5複雑なコーディング、社内システムとの連携
Sonnet 5速度と精度のバランス型
Haiku 4.5軽量・高速。単純作業や大量処理
推論モデル（リーズニングモデル）
答える前に内部で考える工程を持つモデル。計算や複雑な検討で精度が上がる代わりに、時間とコストが増えます。
エフォートEffort
考える量を指定する設定。高くすると回答は徹底的になりますが、時間がかかり、利用制限も速く消費します。
Claudeの表示使いどころ
低即答がほしい単純作業
中軽い調べもの、下書き
高（デフォルト）通常はこのまま
超高込み入った検討・分析
最大制限を気にせず最高精度が要るとき

ChatGPTにも同じ考え方の設定があり、Instant（即答）から順に段階が上がります。上位の段階はPlus以上のプランが必要です。ラベルや並びは頻繁に変わるため、画面の表示を優先してください。

拡張と自動化

AIエージェント
複数の手順を自分で判断しながら実行するAI。作業代行型・開発型がこれにあたります。
サブエージェント
大きな作業を分担させるため、AIが別のAIを呼び出す仕組み。調査と執筆を分けるといった使い方をします。
MCP（コネクタ）
AIを外部ツール（カレンダー、ストレージ、社内システム）につなぐ共通規格（→第7部）。
アーティファクト
AIが作った成果物を、会話とは別枠で表示・保存する仕組み（→第6部 Claude）。
スキル / プラグイン
よく使う手順をパッケージ化して覚えさせる仕組み。「議事録はこの形式で」といった型を毎回説明せずに再利用できます。
カスタムAI（Gem / GPTs / プロジェクト）
役割と参照資料を持たせた専用のAIを作る機能。呼び方はツールごとに違いますが中身は同じ考え方です（→第4部「専門家をつくる」）。
GASGoogle Apps Script
Googleのサービス上で動く小さなプログラム。スプレッドシート、Gmail、ドライブ、カレンダーを操作でき、時刻を決めて自動実行できます。追加の契約は要りません。やりたいことを日本語で伝えればAIが書くので、貼り付けて動かすだけです。
SQL
データベースから必要なデータだけを取り出すための言語。「この条件のデータを、この並びで」と指示します。これもAIに書かせられます。

安全と制御

Human in the Loop
人間が必ず途中に入る設計。責任の所在を人間側に置くための考え方です。
ガードレール
AIが出力してはいけない内容を制限する仕組み。社内ルールを守らせるために設定します。
プロンプトインジェクション
資料やWebページに仕込まれた文章を、AIが指示として読み取ってしまう攻撃。社外から届いたファイルをそのままAIに処理させる運用は避けてください。
