第 1 部

ツールの5分類

分類の一覧

分類の基準は2つ。成果物がどこに残るかと、どこまで自走するかです。中身のAIはどれもほぼ同じもので、性能差より設計思想の差のほうが実務では効きます。

分類代表成果物の置き場所動き方
チャット型Claude / ChatGPT / Gemini会話の中一往復で答える
作業代行型CoworkPCのフォルダ複数手順を自走。定期実行も可
開発型Claude Code / Codexコードとして手元に残る同上＋履歴管理・動作確認
デザイン型Claude Design書き出し先（Canva等）指示からビジュアルを生成
資料限定型Gemini Notebookノートブックの中渡した資料だけを根拠に答える

選択の判断軸

  1. 成果物は何か — 答えだけ→チャット型／ファイル→作業代行型・開発型／画像→デザイン型
  2. 手順は毎回同じか — 同じ→開発型（スクリプトとして残る）／毎回違う→作業代行型
  3. 根拠を追う必要があるか — ある→資料限定型

誤解されやすい点

開発型はエンジニア専用ではありません。毎月同じ集計、決まった形式での取り込みなど、手順が固定していて再現性が要る作業は、非エンジニアでも開発型が適します。スクリプトとして残るため、他の人にも渡せます。判断軸は職種ではなく手順の固定度です。

Claude Code もチャット形式です。「このバグを直して」と日本語で頼めます。ターミナルが原点ですが、デスクトップアプリ・Web・VS Code拡張でも同じことができます。

第 2 部

業務別カタログ
全自動 人は結果を確認するだけ。定期実行に載せられる
半自動 AIが作り、人が確認・修正して確定する
支援 人が主体。AIは検討相手

A. 書く・まとめる

業務度合いツール補足
メール・チャットの下書き半自動チャット型送信は人が判断する
議事録の作成（文字起こしから）半自動チャット型 作業代行型形式が決まっているならCoworkに型を登録する
長文資料の要約半自動チャット型数字と固有名詞は要確認
報告書・提案書の作成半自動作業代行型Word / PowerPointで出す場合
翻訳・誤字チェック全自動チャット型答えがほぼ一意。エフォートは「低」で足りる
定型フォーマットへの変換全自動作業代行型毎回同じ形なら開発型でも可

B. 調べる・確認する

業務度合いツール補足
社内規程・マニュアルの検索全自動資料限定型一般知識で補完しないため根拠を追える
分厚い資料の横断調査半自動資料限定型100ページ超でも扱える
契約書・仕様書の矛盾チェック半自動チャット型エフォートは「高〜超高」。見落としのコストが待ち時間を上回る
競合・市場の調査半自動チャット型出典を確認する
数値データの異常検知全自動開発型手順が固定なのでスクリプト化が確実

C. 集める・整える（データ）

業務度合いツール補足
複数ファイルの集計・突合全自動作業代行型フォルダを渡すだけ
毎週・毎月の定期レポート全自動作業代行型時刻を指定して自動実行
外部サービスからのデータ取り込み全自動開発型手順が固定ならスクリプトが確実。他の人にも渡せる
大量データの取り込み・分析全自動開発型件数が多いほど開発型が有利（第3部の実例を参照）
ファイルの命名・仕分け全自動作業代行型

D. 作る（ビジュアル・ツール）

業務度合いツール補足
バナー・資料デザインの量産半自動デザイン型社内のロゴ・配色を読み込ませるとブランドが揃う
画像の生成半自動チャット型 デザイン型ChatGPT Images 2.0、Gemini Nano Banana Pro など
図解・インフォグラフィックの作成半自動チャット型日本語の文字入り画像はNano Banana Proが安定
業務ツールの自作半自動開発型継続的に手を入れる場合
社内向けの1枚ツール半自動作業代行型HTML1枚で完結するならCoworkが速い
社内マニュアルの整備半自動作業代行型

E. 考える・決める

業務度合いツール補足
アイデア出し・企画の検討支援チャット型往復して精度を上げる性質の作業
分析結果からの施策立案支援チャット型分析（自動）と立案（人）を分ける
意思決定の材料づくり支援チャット型エフォート「最大」。判断そのものは人が行う
採用・評価・人事判断任せない—参考意見に留める

自動化に向かない業務

  • 例外処理が多い業務（毎回イレギュラーが発生する）
  • 正解が一つに定まらない創造的判断
  • 最終責任を伴う判断（契約、人事、法務の確定）
  • 相手の感情が絡むコミュニケーション

無理に自動化すると、手戻りのコストが削減分を上回ります。

第 3 部

導入の進め方

3段階で進める

  1. 手作業でやってみる。そのとき手順を箇条書きにする。これが設計図になる
  2. 半自動で運用する。AIが作り、人が毎回チェックする。ここで精度と例外が見える
  3. 精度を確認してから全自動化する。定期実行に載せるのは最後

②を省略すると、AIの出力が的外れでも気づかないまま運用が続きます。最初の1〜2か月は人が見る前提で組んでください。

実例：大量クリエイティブの分析

「1,000件のクリエイティブ（画像URL）と数値を取り込み、勝ちパターンを資料化し、次の案を出す」という業務での設計例です。

全件をそのままAIに渡すと破綻します。画像1枚は約1,000〜2,000トークン。1,000枚なら100万トークンを超え、一度に扱える上限（約20万トークン）を大きく超過します。そこで、数値で絞ってから画像を見せる構成にします。

工程やることツール度合い
① 取り込みURLから画像と数値を収集開発型全自動
② 絞り込み数値だけで上位・下位を抽出開発型全自動
③ 言語化上位20件・下位20件の画像だけを見せて共通点を出す開発型半自動
④ 資料化勝ちパターンをレポートにまとめる開発型 作業代行型半自動
⑤ 案出し勝ちパターンから次の案を出すチャット型支援
⑥ ビジュアル化案を実際の画像にするデザイン型半自動

②で画像を扱わないため処理は一瞬で終わり、③に渡るのは40枚だけ。100万トークンが数万トークンに収まります。

⑤は自動化の対象外です。案出しは正解が一つに定まらないため、方向を変えながら往復する余地を残したほうが結果が良くなります。①〜④は毎月同じ手順で回るので、スクリプトとして残る開発型が適します。

第 4 部

ツール別の詳細

Claudeクロード チャット型

Anthropic社のAIアシスタント。長文の読み書き、機微な文書、推敲に強みがあります。

  • 向いている：相談、下書き、推敲、資料を貼っての質問
  • 向かない：手元のファイルを直接書き換えること、繰り返し実行する作業

Claude Code 開発型

コードを読み書きするAIエージェント。やりとりはチャット形式で、日本語で指示できます。ターミナルが原点ですが、デスクトップアプリ・Web・VS Codeなどのエディタ拡張でも同じことができます。

  • 向いている：継続的に手を入れるコード、手順が固定した業務自動化
  • 向かない：一度きりの書類作成
  • 特徴：変更履歴が残るため、壊しても元に戻せる

Coworkコワーク 作業代行型

フォルダを渡すと、ファイルを読んで成果物を作って返します。ダウンロードの工程がない点が特徴です。

  • 向いている：フォルダ内の資料整理、定期レポート、1枚で完結するツール、決まった時刻に走らせる作業
  • 向かない：継続的に育てるコード。作業環境が毎回リセットされ、変更履歴も残らない

Claude Codeとの境界は、継続的に手を入れるかどうかです。育てるならCode、一度作って終わりならCowork。

Claude Design デザイン型

テキスト指示でUI・バナー・LP・資料のビジュアルを生成します（2026年4月公開）。社内のロゴ・配色・コンポーネントをデザインシステムとして読み込ませると、それに沿った成果物を出せます。Claude Codeとの双方向連携、Canva・Adobe・Miroへの書き出しに対応。

  • 向いている：ブランドを揃えたバナー・資料・画面デザインの量産
  • 向かない：文章中心の作業

ChatGPT チャット型

OpenAI社のAIアシスタント。利用者が最も多く、参考情報も豊富です。

  • 向いている：汎用的な相談、下書き、アイデア出し、画像生成
  • 画像生成（Images 2.0）：2026年4月から、ChatGPT・Codex・APIのいずれからも利用可。日本語テキストの描画精度が高く、1回で最大8枚まで同時生成。商用利用可。思考モードはPlus以上

Codexコーデックス 開発型

OpenAI社の開発者向けエージェント。Claude Codeと同じ位置づけです。

  • 向いている：コードを書く・直す、手順が固定した業務自動化
  • 画像生成：Images 2.0 を Codex から呼べるため、生成して組み込む流れが1環境で完結する

Claude Codeとの選び方。普段使っているサービス側に合わせるのが、契約とアカウント管理の面ではシンプルです。ただし両者は得意分野が異なり、同じ課題を両方に投げて出力を比べる使い方も一般的です。片方に絞らなければならない理由はないので、重要な作業では併用も検討してください。

Geminiジェミニ チャット型

Google社のAI。

  • 向いている：Googleドキュメント、スプレッドシート、Gmailと絡む業務、画像生成
  • 向かない：Workspaceの外での文章作業（他のチャット型で足りる）

画像生成（Nano Banana Pro）

Geminiの画像生成モデルは通称「Nano Banana」系で、上位版が Nano Banana Pro（正式名称 Gemini 3 Pro Image）です。従来版の弱点だった文字の崩れと低解像度が大きく改善され、日本語の文字が入った図解やバナーを作りやすくなりました。最大6枚の画像を光や影を揃えて合成する機能もあります。

無料プランは1日約3枚、Google AI Pro（月額約2,900円）で1日約100枚。ただしProで生成するには標準版で作ってから「Proで再生成」する2ステップが必要で、生成枠を2回分消費します。

Gemini Notebook旧 NotebookLM 資料限定型

アップロードした資料だけを根拠に答えるツール。2026年7月に「NotebookLM」から改称されました。

  • 向いている：分厚いマニュアルや過去議事録の調査。根拠を追える
  • 向かない：アップロードしていない情報に関する質問。手元の資料に書かれていないことは答えられない

第 5 部

用語集

基本

生成AI
文章・画像・コードなどを新しく作り出すAI。検索が既存の情報を探して見せるのに対し、生成AIはその場で文章を組み立てます。そのため正解は保証されません。
LLM（大規模言語モデル）
ChatGPTやClaudeの中身。膨大な文章から「次に来る言葉」を予測する仕組みで動いています。意味を理解しているというより、それらしい続きを高い精度で組み立てている、という理解が実態に近いです。
プロンプト
AIへの指示文。出力の質はここでほぼ決まります。
マルチモーダル
文字だけでなく画像・音声・PDFも扱えること。
API
プログラムからAIを呼び出す仕組み。アプリの画面を経由せず自社システムに組み込むときに使います。料金はトークン単位の従量課金。

精度と限界

ハルシネーション
AIが事実でないことを、自信のある書き方で出力する現象。仕組み上どうしても発生するもので、故障ではありません。ゼロにはできないため、確認する運用でカバーします。
知識のカットオフ
モデルが学習した情報の締め切り時点。それ以降の出来事は知りません。最近の情報が必要なときは、検索機能を使うか、資料を添付します。
グラウンディング
出力を実在の情報源に紐づけること。検索結果や添付資料を根拠にさせると、ハルシネーションが減り、出典を確認できます。
RAG（検索拡張生成）
指定した資料に基づいて答えさせる仕組み。資料限定型はこれに特化したツールです。
埋め込み（ベクトル検索）
文章を数値の並びに変換し、意味の近さで検索する技術。キーワードが一致しなくても内容が近い文書を拾えます。RAGの内部で使われています。

分量とコスト

トークンはAIが文章を処理する単位。日本語は1文字＝1〜2トークン。料金や上限はこの単位で数えます。

依頼の例トークン目安
「これ英語で何て言う？」〜100
メールの下書き約1,000
議事録の作成（A4 2〜3枚）約8,000
画像1枚を見せて質問約1,000〜2,000
60分の文字起こしを要約約30,000
30ページのPDFを要約約60,000
100ページの規程集をチェック約150,000〜

コンテキストウィンドウは一度に扱える情報量の上限で、おおむね20万トークン前後です。会話が長くなると古い部分から実質的に薄れるため、「先に伝えたのに反映されない」という現象が起きます。

会話は毎回すべて読み直されます。10往復目の発言は、それまでの全履歴分のトークンを消費します。話題が変わったら新しい会話を立てるほうが速く、消費も抑えられます。

モデルと設定

モデルはAIの種類・世代。同じサービスでも選ぶモデルで賢さ・速さ・コストが変わります。難しい仕事は高性能モデル、単純作業は軽量モデルが基本です。

Claudeのモデル（※2026年7月時点）位置づけ
Fable 5最も困難な課題に
Opus 5複雑なタスク向け
Sonnet 5日常のタスクに最も効率的
Haiku 4.5素早い回答に最適
推論モデル（リーズニングモデル）
答える前に内部で考える工程を持つモデル。計算や複雑な検討で精度が上がる代わりに、時間とコストが増えます。
温度（Temperature）
出力のばらつきを決める設定。低いと堅実で再現性が高く、高いと発想が広がる代わりに不安定になります。アプリ画面では触れないことが多く、主にAPI利用時の設定項目です。
ファインチューニング
特定の業務データを追加学習させ、モデル自体を専用化すること。効果は大きい一方、費用と手間がかかります。多くの業務は、資料を渡すRAGで足ります。
オープンウェイトモデル
中身が公開されており、自社サーバーで動かせるモデル。外部にデータを出せない業務で選択肢になります。

エフォートEffort

考える量を指定する設定。高くすると回答は徹底的になりますが、時間がかかり、利用制限も速く消費します。

Claudeの表示使いどころ
低即答がほしい単純作業
中軽い調べもの、下書き
高（デフォルト）通常はこのまま
超高込み入った検討・分析
最大制限を気にせず最高精度が要るとき

ChatGPTは設定が4項目に分かれています（モデル / 推論レベル / 速度 / 詳細設定）。エフォートにあたるのは「推論レベル」で、Claudeと違い「速度」が独立しています。

運用としては、基本は「高」のまま使い、急ぐ単純作業だけ下げ、精度が要る場面だけ上げる形が扱いやすいです。

拡張と自動化

AIエージェント
複数の手順を自分で判断しながら実行するAI。作業代行型・開発型がこれにあたります。
サブエージェント
大きな作業を分担させるため、AIが別のAIを呼び出す仕組み。調査と執筆を分けるといった使い方をします。
MCP（コネクタ）
AIを外部ツール（カレンダー、ストレージ、社内システム）につなぐ共通規格。AIが自分でデータを見に行けるようになります。
スキル / プラグイン
よく使う手順をパッケージ化して覚えさせる仕組み。「議事録はこの形式で」といった型を毎回説明せずに再利用できます。
Human in the Loop
人間が必ず途中に入る設計。責任の所在を人間側に置くための考え方です。
ガードレール
AIが出力してはいけない内容を制限する仕組み。社内ルールを守らせるために設定します。

セキュリティ

プロンプトインジェクション
攻撃者が資料やWebページに仕込んだ文章を、AIが指示として読み取ってしまう攻撃。外部から取り込んだ文書をAIに読ませる場合は、出力に不自然な指示が混じっていないか確認が必要です。社外から届いたファイルをそのままAIに処理させる運用は避けてください。

使い方のコツ

  1. 役割を与える … 「経験10年の法務担当として」と前置きするだけで語彙も観点も変わります
  2. 前提と制約を渡す … 目的・読み手・分量・トーン・使ってはいけない表現の5点
  3. 例を見せる … 過去の良い成果物を2〜3個貼る。説明するより正確に伝わります
  4. 段階的に考えさせる … 「結論の前に判断の過程を書いて」と頼むと精度が上がります
  5. 一発で終わらせない … 最初の出力は下書き。往復を前提にする

プロンプトの文言を調整するより、渡す材料を整えるほうが効果が大きい傾向があります（コンテキストエンジニアリング）。関連資料、過去の議事録、フォーマット見本を揃えることを優先してください。

第 6 部

運用ルール

入力してはいけない情報

  • 顧客の個人情報、取引先の非公開情報
  • 未公開の財務数値、人事情報
  • パスワード、APIキー、認証情報

判断基準は「これが外部に出ても困らないか」です。困るものは入力しない。

学習利用の設定

入力内容がAIの学習に使われるかは、プラン・設定によって変わります。法人契約では通常オフですが、個人アカウントでの業務利用は避けてください。

出力の責任

AIが書いた文章でも、送信するのは人間です。数字・人名・法令は必ず確認してください。

著作権と社外公開

AIが生成した文章や画像をそのまま社外公開する場合は、事前に確認をとってください。既存著作物に酷似するケースがまれにあります。

運用の原則

  1. 業務を「全自動 / 半自動 / 支援」に仕分ける。すべてを自動化しようとしない
  2. ツールは成果物の置き場所で選ぶ。性能の差ではない
  3. 半自動の期間を経てから全自動にする
質問・追記の要望は情報システム部門まで。
