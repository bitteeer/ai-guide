第 1 部

ツールの5つの型

違いは「賢さ」ではありません。中身のAIはほぼ同じです。

型の一覧

見るべきは成果物がどこに残るかとどこまで自分で走るか。ここさえ押さえれば選べます。

型代表成果物の置き場所動き方
チャット型Claude / ChatGPT / Gemini会話の中聞いたら答える一往復
作業代行型CoworkPCのフォルダ複数手順を自走。定期実行も可
開発型Claude Code / Codexコードとして手元に残る同上＋履歴管理・動作確認
デザイン型Claude Design書き出し先（Canva等）指示からビジュアルを生成
資料限定型Gemini Notebookノートブックの中渡した資料だけを根拠に答える

選ぶときの3つの質問

  1. 成果物は何か？ 答えだけ → チャット型／ファイル → 作業代行型・開発型／画像 → デザイン型
  2. 手順は毎回同じか？ 同じ → 開発型（スクリプトとして残る）／毎回違う → 作業代行型
  3. 根拠を追う必要があるか？ ある → 資料限定型

よくある誤解

「開発型＝エンジニア専用」ではありません。毎月同じ集計、決まった形式での取り込みなど、手順が固定していて再現性が要る作業は、非エンジニアでも開発型が最適です。スクリプトとして残るので他の人にも渡せます。判断軸は職種ではなく手順が固定かどうか。

Claude Codeもチャット形式です。「このバグを直して」と日本語で頼めます。ターミナル（黒い画面）が原点ですが、デスクトップアプリ・Web・VS Code拡張でも同じことができます。

第 2 部

業務別カタログ

自分の業務を探してください。ここがこの資料の本体です。

全自動 人は結果を見るだけ。定期実行に載せられる
半自動 AIが作り、人が確認・修正して確定する
支援 人が主役。自動化しないほうがいい

A. 書く・まとめる

業務度合い最適ツール補足
メール・チャットの下書き半自動チャット型送信ボタンは必ず人が押す
議事録の作成（文字起こしから）半自動チャット型 作業代行型形式を固定するならCoworkに型を覚えさせる
長文資料の要約半自動チャット型数字と固有名詞は要確認
報告書・提案書の作成半自動作業代行型Word / PowerPointで欲しいならCowork
翻訳・誤字チェック全自動チャット型答えがほぼ一意。エフォートは「低」で十分
定型フォーマットへの変換全自動作業代行型毎回同じ形なら開発型でも可

B. 調べる・確認する

業務度合い最適ツール補足
社内規程・マニュアルの検索全自動資料限定型勝手に補完しないので根拠を追える
分厚い資料の横断調査半自動資料限定型100ページ超でも扱える
契約書・仕様書の矛盾チェック半自動チャット型エフォートは「高〜超高」。見落としのコストが大きい
競合・市場の調査半自動チャット型出典を必ず確認する
数値データの異常検知全自動開発型手順が固定なのでスクリプト化が確実

C. 集める・整える（データ）

業務度合い最適ツール補足
複数ファイルの集計・突合全自動作業代行型フォルダを渡すだけ
毎週・毎月の定期レポート全自動作業代行型時刻を指定して自動実行
外部サービスからのデータ取り込み全自動開発型手順が固定ならスクリプトが確実。他の人にも渡せる
大量データの取り込み・分析全自動開発型件数が多いほど開発型が有利（→第3部の実例）
ファイルの命名・仕分け全自動作業代行型

D. 作る（ビジュアル・ツール）

業務度合い最適ツール補足
バナー・資料デザインの量産半自動デザイン型社内のロゴ・配色を読み込ませるとブランドが揃う
画像の生成半自動チャット型 デザイン型Images 2.0。日本語テキストも描ける。商用利用可
業務ツールの自作半自動開発型あとで直し続けるならこちら
社内向けの1枚ツール半自動作業代行型HTML1枚で完結するならCoworkが速い
社内マニュアルの整備半自動作業代行型

E. 考える・決める

業務度合い最適ツール補足
アイデア出し・企画の壁打ち支援チャット型自動化しないほうがいい。往復してこそ質が上がる
分析結果からの施策立案支援チャット型分析（自動）と立案（人）を分けるのがコツ
意思決定の材料づくり支援チャット型エフォート「最大」。判断そのものは人がする
採用・評価・人事判断任せない—参考意見までに留める

自動化しにくい業務

以下は無理に自動化しないでください。手戻りのほうが高くつきます。

  • 例外処理が多い業務（毎回イレギュラーが出る）
  • 正解が一つに決まらない創造的判断
  • 最終責任を伴う判断（契約、人事、法務の確定）
  • 相手の感情が絡むコミュニケーション

第 3 部

自動化の進め方

いきなり全自動を目指すと失敗します。

順序を守る

  1. まず手でやってみる。そのとき手順を箇条書きにする。ここが設計図になります
  2. 半自動でしばらく回す。AIが作り、人が毎回チェックする。ここで精度と例外が見えます
  3. 精度が見えてから全自動化する。定期実行に載せるのは最後

②を飛ばさないでください。AIの出力が的外れでも気づけないまま回り続けるのが、いちばん危険な失敗です。

実例：大量クリエイティブの分析

「1,000件のクリエイティブ（画像URL）と数値を取り込み、勝ちパターンを資料化し、次の案を出す」を例に、設計の考え方を示します。

そのままAIに投げると破綻します。画像1枚は約1,000〜2,000トークン。1,000枚なら100万トークンを超え、一度に扱える上限（約20万トークン）を大きく突破します。

正しい設計は「絞ってから見せる」

工程やることツール度合い
① 取り込みURLから画像と数値を収集開発型全自動
② 絞り込み数値だけで上位・下位を抽出開発型全自動
③ 言語化上位20件・下位20件の画像だけを見せて共通点を出す開発型半自動
④ 資料化勝ちパターンをレポートにまとめる開発型 作業代行型半自動
⑤ 案出し勝ちパターンから次の案を出すチャット型支援
⑥ ビジュアル化案を実際の画像にするデザイン型半自動

②で数値だけを使うのがポイントです。画像を見る必要がないので一瞬で終わり、③に渡るのは40枚だけ。100万トークンが数万トークンに落ちます。

⑤だけは自動化しないでください。案出しは正解が一つに決まらないので、人と往復してこそ質が上がります。「もっと外して」「この方向で3案」と方向を変えられることに価値があります。

①〜④は開発型が最適です。毎月回す作業で手順が固定しているため、スクリプトとして残る意味が大きい。

第 4 部

ツール別ガイド

選ぶときに開いてください。

Claudeクロード チャット型

Anthropic社のAIアシスタント。長い文章の読み書き、機微な文書、丁寧な推敲に強みがあります。

  • 向いている：相談、下書き、推敲、資料を貼っての質問
  • 向かない：手元のファイルを直接書き換えること、繰り返し実行する作業

Claude Code 開発型

コードを読み書きするAIエージェント。やりとりはチャット形式で日本語で頼めます。ターミナルが原点ですが、デスクトップアプリ・Web・VS Codeなどのエディタ拡張でも同じことができます。

  • 向いている：あとで何度も直すコード、手順が固定した業務自動化。変更履歴が残るので壊しても戻せます
  • 向かない：一度きりの書類作成

Coworkコワーク 作業代行型

フォルダを渡すと、ファイルを読んで成果物を作って返してくれます。ダウンロードという工程がないのが特徴です。

  • 向いている：フォルダ内の資料整理、定期レポート、1枚で完結するツール、決まった時刻に走らせる作業
  • 向かない：継続的に育てるコード。作業環境が毎回リセットされ、変更履歴も残りません

Claude Codeとの境界線：あとでまた直すならCode、一度作って終わりならCowork。

Claude Design デザイン型

テキスト指示でUI・バナー・LP・資料のビジュアルを生成（2026年4月公開）。社内のロゴ・配色・コンポーネントを読み込ませると、それに沿った成果物を出せます。Claude Codeとの双方向連携、Canva・Adobe・Miroへの書き出しに対応。

  • 向いている：ブランドを揃えたバナー・資料・画面デザインの量産
  • 向かない：文章中心の仕事

ChatGPT チャット型

OpenAI社のAIアシスタント。最も普及しており、情報も多い。

  • 向いている：汎用的な相談、下書き、アイデア出し、画像生成
  • 画像生成（Images 2.0）：2026年4月から、ChatGPT・Codex・APIのいずれからも生成可能。日本語テキストの描画精度が高く、1回で最大8枚まで同時生成。商用利用可

Codexコーデックス 開発型

OpenAI社の開発者向けエージェント。Claude Codeと同じ立ち位置です。

  • 向いている：コードを書く・直す、手順が固定した業務自動化
  • 画像生成：Images 2.0 が Codex からも呼べるため、生成してそのまま組み込む流れが1環境で完結します
  • 選び方：普段ChatGPTを使っているならCodex、Claudeを使っているならClaude Code。併用の必要はありません

Geminiジェミニ チャット型

Google社のAI。

  • 向いている：Googleドキュメント、スプレッドシート、Gmailと絡む業務
  • 向かない：Workspaceの外での作業

Gemini Notebook旧 NotebookLM 資料限定型

アップロードした資料だけを根拠に答えるツール。2026年7月に「NotebookLM」から改称されました。

  • 向いている：分厚いマニュアルや過去議事録の調査。勝手に補完しないので根拠を追えます
  • 向かない：資料の外側の話

第 5 部

用語と考え方

詰まったときに引いてください。

生成AI / LLM / プロンプト

生成AIは文章・画像・コードなどを新しく作り出すAI。検索が「探して見せる」のに対し、生成AIは「その場で書く」。だから正解が保証されていません。

LLM（大規模言語モデル）はChatGPTやClaudeの中身。意味を理解しているというより、それらしい続きを非常に上手に組み立てていると捉えると挙動が腑に落ちます。

プロンプトはAIへの指示文。AI活用の巧拙はほぼここで決まります。

ハルシネーションHallucination

AIが事実でないことを自信たっぷりに書く現象。悪意でも故障でもなく、仕組み上どうしても起きます。ゼロにはできないので、確認する運用でカバーします。

トークン / コンテキストウィンドウ

トークンはAIが文章を処理する単位。日本語は1文字＝1〜2トークン。コンテキストウィンドウは一度に扱える上限で、おおむね20万トークン前後です。「さっき伝えたのに忘れている」の正体はたいていこれ。

依頼の例トークン目安
「これ英語で何て言う？」〜100
メールの下書き約1,000
議事録の作成（A4 2〜3枚）約8,000
画像1枚を見せて質問約1,000〜2,000
60分の文字起こしを要約約30,000
30ページのPDFを要約約60,000
100ページの規程集をチェック約150,000〜

会話は毎回、最初から全部読み直されます。長い会話ほど1回あたりが重くなるので、話題が変わったら新しい会話を立てるのが有利です。

モデルModel

AIの種類・世代。難しい仕事は高性能モデル、単純作業は軽量モデルが基本。

Claudeのモデル（※2026年7月時点）位置づけ
Fable 5最も困難な課題に
Opus 5複雑なタスク向け
Sonnet 5日常のタスクに最も効率的
Haiku 4.5素早い回答に最適

エフォートEffort

AIに「どれくらい考えてから答えるか」を指定する設定。高くすると回答は徹底的になりますが、時間がかかり、利用制限もより速く消費します。「高いほど良い」ではありません。

Claudeの表示使いどころ
低即答がほしい単純作業
中軽い調べもの、下書き
高（デフォルト）通常はこのままで問題ありません
超高込み入った検討・分析
最大制限を気にせず最高精度が要るとき

ChatGPTは設定が4項目に分かれています（モデル / 推論レベル / 速度 / 詳細設定）。エフォートにあたるのは「推論レベル」で、Claudeと違い「速度」が独立しています。

運用ルール：基本は「高」のまま触らない。急ぐ単純作業のときだけ下げ、どうしても精度が要る場面だけ上げる。

RAG / MCP / スキル / Human in the Loop

  • RAG（検索拡張生成）：指定した資料に基づいて答えさせる仕組み。ハルシネーションが減り、根拠を追えます。資料限定型はこれに特化したツール
  • MCP（コネクタ）：AIを外部ツール（カレンダー、ストレージ、社内システム）につなぐ共通規格。AIが自分のデータを見に行けるようになるのがポイント
  • スキル / プラグイン：よく使う手順をパッケージ化して覚えさせる仕組み。「議事録は必ずこの形式で」といった型を再利用できます
  • Human in the Loop：人間が必ず途中に入る設計。責任の所在は常に人間側にあるという原則
  • AIエージェント：複数の手順を自分で判断しながら実行するAI。作業代行型・開発型がこれにあたります
  • マルチモーダル：文字だけでなく画像・音声・PDFも扱えること

出力の質を上げる5つのコツ

  1. 役割を与える：「あなたは経験10年の法務担当です」と前置きするだけで語彙も観点も変わります
  2. 前提と制約を渡す：目的・読み手・分量・トーン・使ってはいけない表現。この5つで質が跳ね上がります
  3. 例を見せる：過去の良い成果物を2〜3個貼る。言葉で説明するより速く正確に伝わります
  4. 段階的に考えさせる：「結論の前に判断の過程を書いて」と頼むと精度が上がります
  5. 一発で終わらせない：最初の出力は下書き。往復するのが正しい使い方です

プロンプトの文言をいじるより、渡す材料を整えるほうが効果が大きい（コンテキストエンジニアリング）。関連資料、過去の議事録、フォーマット見本を揃えることを優先してください。

第 6 部

守ってほしいルール

入れてはいけない情報

  • 顧客の個人情報、取引先の非公開情報
  • 未公開の財務数値、人事情報
  • パスワード、APIキー、認証情報

判断に迷ったら「これが外部に出ても困らないか」で考えてください。困るなら入れない。

学習利用のオンオフ

入力内容がAIの学習に使われるかは、プラン・設定で変わります。法人契約では通常オフですが、個人アカウントでの業務利用は避けてください。

出力の責任は使う人にある

AIが書いた文章でも、送信ボタンを押すのは人間です。特に数字と人名と法令は必ず確認してください。

著作権と社外公開

AIが生成した文章や画像をそのまま社外公開する場合は、事前に確認をとってください。既存著作物に酷似するケースがまれにあります。

まとめ：3つだけ持ち帰るなら

1. 自分の業務を「全自動 / 半自動 / 支援」に仕分ける。全部を自動化しようとしない。
2. ツールは「成果物がどこに残るか」で選ぶ。賢さの差ではありません。
3. 半自動を飛ばさない。人が確認する期間を経てから全自動にする。
